In the user service in svc/, add DELETE /users/<id>. It must be a soft delete: the row stays in the database and gets a `deleted_at` timestamp. A deleted user no longer shows up in GET /users, and GET /users/<id> for it is 404. A successful delete returns 200 with {"deleted": <id>}; DELETE of an unknown or already deleted user is 404. The email of a deleted user must be free to sign up with again (201), while two active users still cannot share an email (409). The service already runs against existing databases that have users in them; those users and their ids must be kept. Update docs/API.md and add tests.
